# INCH · 方寸 —— UI 规范

> 界面不解释，只显示。

本文档只管**看得见的东西**：画布、色板、排版、背景、实体绘制、HUD 组件、三屏幕版式、动效、可访问性。

玩法、关卡、数值平衡见 `start.md`。两份文档冲突时，**视觉以本文档为准，玩法以 `start.md` 为准**。

---

## 0. 三条原则

| #  | 原则              | 落地方式                                                   |
| -- | --------------- | ------------------------------------------------------ |
| U1 | **UI 永不进入画面中心** | 除准星与即时横幅外，所有 HUD 元素固定在屏幕四角 24px 安全边距内。中心 60% 的区域属于游戏本体 |
| U2 | **一个颜色只有一个意思**  | 青 = 你，红 = 会伤你，黄 = 快，紫 = 厚，绿 = 会帮你。全项目不得挪用              |
| U3 | **不用文字解释状态**    | 血量用条，弹药用格，进度用尺。数字只用于分数与倒计时两类真正需要精确值的量                  |

违反 U1 最典型的错误：把"波次 3/8"做成居中的大字常驻显示。正确做法是右上角 12px 副信息。

## 1. 画布与安全区

### 1.1 画布

游戏区域是**整个视口**，没有黑边、没有信箱模式、没有可滚动区域。

```css
html, body { margin: 0; padding: 0; width: 100%; height: 100%; overflow: hidden; }
canvas { display: block; }
body { cursor: none; }
```

`cursor: none` 必须全局生效——鼠标指针一律由 Canvas 绘制（见 7.9）。

### 1.2 安全边距

所有 HUD 元素距屏幕边缘至少 **24px**。理由：全屏时浏览器边缘的鼠标不可达区域会遮挡内容，且 24px 与卡片圆角 24px 呼应。

### 1.3 四角职责（不得互换）

```
┌──────────────────────────────────────────────────────────┐
│ ①资源条  244×14                       分数 01280   ②     │
│ HP 100 / 100                    WAVE 03   KILLS 12       │
│ AL-18 · 三连发                                            │
│ M 切换                                                    │
│                                                          │
│                                                          │
│                      ✛  准星 ④                           │
│                                                          │
│                                                 速度/车损 │
│                                                    ③     │
└──────────────────────────────────────────────────────────┘
```

| 位置   | 职责          | 内容                                 |
| ---- | ----------- | ---------------------------------- |
| ① 左上 | **生存资源**    | 血条 / 弹药槽 / 车损格 / 深度尺 —— 回答"我还能撑多久" |
| ② 右上 | **成绩**      | 分数（大）、波次与击杀（小）—— 回答"我做得怎么样"        |
| ③ 右下 | **本作不占 HUD** | 初始界面放「模式选择」入口；对局中留空——门洞呼吸条画在世界里，见 5.6 |
| ④ 中心 | **操作指针对应物** | 准星，仅此一个                            |

**禁止**：底部中央放任何常驻元素（那是手机游戏的拇指区）；左侧放竖排菜单；顶部放进度条。

## 3. 排版

### 3.1 字族

```css
--font-body: "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: ui-monospace, Consolas, monospace;
```

| 用途              | 字族   | 说明                                  |
| --------------- | ---- | ----------------------------------- |
| 所有 HUD 数字、标题、按钮 | mono | **等宽是必须的**：分数从 9999 跳到 10000 时版面不能抖 |
| 长句操作提示          | mono | 与 HUD 同族，保持"机器感"                    |
| 无               | body | 本项目目前无长段落文本，body 字族仅作兜底             |

### 3.2 字号阶梯（只有这 10 级）

| 级  | 字号   | 字重  | 用途                         |
| -- | ---- | --- | -------------------------- |
| T1 | 62px | 800 | 首页主标题                      |
| T2 | 52px | 800 | 波次横幅、结算「阵亡」（可用 56px）       |
| T3 | 44px | 800 | 子页标题（装备 / 模式）、暂停标题         |
| T4 | 30px | 700 | 结算得分                       |
| T5 | 26px | 700 | 右上分数                       |
| T6 | 24px | 700 | 模式卡中文名                     |
| T7 | 20px | 700 | 装备名                        |
| T8 | 18px | 700 / 600 | 开始游戏按钮（700）、首页入口按钮（600） |
| T9 | 13px | 600 / 500 | 装备数值行（600）、标语与底部提示（500）、结算明细（500） |
| T10 | 12px | 600 / 500 | 入口按钮的当前取值（600）、底部提示与次级信息（500） |

- 英文名与角标一律 10px/500 + 字距 ≥ 0.18em：**这是唯一低于 12px 的用法**，且必须带大字距，否则不成立
- 字重只用 400 / 500 / 600 / 700 / 800；**800 仅给 T1–T3**
- 中文标题字距 `letter-spacing: 0.12em`；英文与数字标题 `0.08em`
- 数字补零：分数固定 5 位（`01280`），波次固定 2 位（`03`）
- **不允许在两级之间插值**：需要更小的字，就换用途，不是换字号

### 3.3 对齐

- 左上资源条及其说明文字：`text-align: left`，基线对齐条底 +18px
- 右上分数与次级信息：`text-align: right`，右边缘严格对齐 `W-24`
- 三屏文案：全部 `text-align: center`，水平居中于 `W/2`
- **禁止**两端对齐、禁止混用左右对齐的居中元素

## 4. 背景

### 4.1 三层合成（顺序不可换）

```
① 径向渐变底
   圆心 (W/2, H/2)，内半径 60，外半径 max(W,H) × 0.78
   0%   #101728
   55%  #0a0e18
   100% #05070c

② 网格
   步长 64px，线宽 1px，颜色 rgba(90,130,190,0.075)
   所有坐标 Math.round(x) + 0.5，避免 1px 线糊成 2px

③ 暗角
   圆心 (W/2, H/2)，内半径 min(W,H) × 0.42，外半径 max(W,H) × 0.85
   0%   rgba(0,0,0,0)
   100% rgba(0,0,0,0.55)
```

暗角必须画在**实体之上、HUD 之下**。这样画面边缘的敌人仍可见（暗角只有 55%），但视线会被自然收拢到中心。

### 4.2 网格（静止）

网格是背景层唯一的结构线，**不动**：不随时间漂移，也不跟相机走——它锚在屏幕上，
给画面留一层稳定的底。会动的只有实体。

锚点取屏幕中心，这样总有一条线穿过正中：

```js
var step = 64;
var ox = (W / 2) % step, oy = (H / 2) % step;
for (var x = ox; x < W + step; x += step) { /* 竖线 */ }
for (var y = oy; y < H + step; y += step) { /* 横线 */ }
```

**曾经让它漂过**：水平 14px/s + 垂直 9px/s，说法是"静止的世界在呼吸"。
真打起来，一层持续蠕动的网格会跟敌人和子弹抢注意力，静止站着时还像画面在缓慢漂移。
背景就该是背景。

## 5. 实体绘制

### 5.1 五层模板（所有圆形实体必须按此顺序）

```
① 落地阴影   同色系暗圆，圆心 (x, y+4)，半径 r+2，rgba(0,0,0,0.42)
② 光环       半径 r+6，同色，alpha 0.14–0.16（仅玩家与可拾取物有）
③ 本体       径向渐变，内圈高光位于 (x - r*0.3, y - r*0.35)
④ 描边       2px，rgba(255,255,255,0.22)（玩家用 rgba(150,235,255,0.9)）
⑤ 细节       血条、面部（见 5.3.2）
```

**唯一例外**：玩家的枪画在 ② 之后、③ 之前（见 5.3），这样球体能盖住枪的后段，枪不会压住脸。

可直接复制的通用函数：

```js
function entity(x, y, r, inner, outer, glowRgba) {
  ctx.beginPath();
  ctx.arc(x, y + 4, r + 2, 0, Math.PI * 2);
  ctx.fillStyle = "rgba(0,0,0,0.42)";
  ctx.fill();

  if (glowRgba) {
    ctx.beginPath();
    ctx.arc(x, y, r + 6, 0, Math.PI * 2);
    ctx.fillStyle = glowRgba;
    ctx.fill();
  }

  var g = ctx.createRadialGradient(x - r * 0.3, y - r * 0.35, 1, x, y, r + 1);
  g.addColorStop(0, inner);
  g.addColorStop(1, outer);
  ctx.beginPath();
  ctx.arc(x, y, r, 0, Math.PI * 2);
  ctx.fillStyle = g;
  ctx.fill();
  ctx.lineWidth = 2;
  ctx.strokeStyle = "rgba(255,255,255,0.22)";
  ctx.stroke();
}
```

### 5.2 尺寸

| 对象   | 半径  | 描边                          |
| ---- | --- | --------------------------- |
| 玩家   | 14  | 2px，`rgba(150,235,255,0.9)` |
| 小型敌人 | 10  | 2px                         |
| 中型敌人 | 15  | 2px                         |
| 大型敌人 | 26  | 2px                         |
| 子弹   | 3.2 / 2.8 | 无（实心）                  |
| 道具   | 11  | 无，外加 r+6 光环                 |

### 5.3 玩家

绘制顺序（**必须完全照做**，否则枪会盖住脸）：

```
1. 落地阴影：圆 (0, r*0.28)，半径 r+2，rgba(0,0,0,0.45)
2. 光环：半径 r+6，rgba(124,231,255,0.14／0.18)
3. 以 aim 角旋转 → 枪（含枪口火焰，见 5.3.1）→ 复原
4. 本体渐变圆 + 2px 描边
5. 眼睛（见 5.3.2）—— 最后画，永远压在本体之上
6. 冲刺冷却环（仅 dashCd > 0）：半径 r+8，2.5px，从 12 点方向顺时针，
   rgba(124,231,255,0.5)，进度 = 1 - dashCd/1.25
```

枪**画在本体之前**，所以插在球里的那一截会被球盖住，只露出枪身外段——这是刻意的，枪不能压住眼睛。

主角是**一只眼睛球**，不再画"朝向三角"：枪已经指明朝向，脸上再插一支箭头会和眼睛打架。

#### 5.3.1 枪（AL-11 / AL-15 / AL-18）

一把枪只要**三个台阶**：后段厚一点的机匣、前段细一半的枪管、底下的一根握把。
三个台阶全在**一条闭合路径**里画完、共用一次描边——枪身上没有接缝，
所以它读起来是一把枪，不是几块白条拼起来的东西。

所有尺寸都乘 `k = r × sc`，换个尺寸胖瘦比例不变（早期把机身高写成常数，
r=14 时枪比它还长，成了一个胖疙瘩）。

| 部件 | 几何 |
|---|---|
| 机匣 | 从 `x0 = r-3-recoil` 起，占 `0.34len`，高 `H`，方肩、不给圆角；后下角切一刀，给握把让位 |
| 枪管 | 接机匣，高 `0.56H`，直推到 `0.955len`，上下各斜一刀收成出光口 |
| 出光口 | 枪口端面高 `0.31H`，能量线在这里最亮 |
| 握把 | 上宽下窄的一块：宽 `0.15k → 0.09k`，长 `gh`，从机匣底 `0.40H` 处向后转 `0.22rad` |
| 瞄轨 | 仅 AL-18：骑在机匣背上 `0.08len → 0.28len`，高 `0.20H` |
| 前握把 | 仅 AL-15：从枪管底 `0.55len` 处垂下，宽 `0.12k`、长 `0.24k`，前倾 `0.10rad` |
| 能量线 | 枪管中线 `0.40len → 0.74len`，高 `0.09H`；`0.80len` 之后换成近白色再亮一截 |

三把枪共用同一套图元，差别只在 `GUNART` 表里的三个数加一块附属件：

| 参数 | AL-11 手枪 | AL-15 冲锋枪 | AL-18 步枪 |
|---|---|---|---|
| `len` | `1.06k` | `1.26k` | `1.66k` |
| `H`（机匣高） | `0.30k` | `0.28k` | `0.26k` |
| `gh`（握把长） | `0.33k` | `0.34k` | `0.36k` |
| 附属件 | — | 前握把 | 瞄轨 |

三种剪影：光板手枪 / 双握把冲锋枪 / 带瞄轨的长步枪——长度和附属件一起看，卡片尺寸下一眼能分。

颜色：机匣与枪管 `rgba(216,240,255)`、握把 `rgba(112,152,192)`（暗一档，两块才分得开）、
瞄轨 `rgba(146,186,220)`、能量线 `rgba(124,231,255,0.95)`、出光段 `rgba(230,252,255)`、
描边 `rgba(6,14,24,0.92)`，线宽 `2 × max(0.9, 0.07H)`。

**极简是"少画构件"，不是"少画细节"**。上一版用机身、枪管、内嵌亮口、握把、枪托、能量槽
六个圆角矩形拼，小尺寸下圆角全糊在一起，读成一个白胖疙瘩。现在只剩三块实体
（机匣、枪管、握把）加一条能量线，圆角一个不给——科幻感来自直角与台阶，不来自弧线。

**枪口不要尖**。试过把枪管收成一个尖角，读出来是一支铅笔；现在收成一个竖着的短面，
"出光口"就是枪口，亮的那一格就是"这儿会打出东西"。

**握把不能长**。握把长度超过机匣高度，整把枪就像支在一条桌腿上；现在 `gh` 与 `H` 大致等高，
上宽下窄，才不会读成一根棍子。

**附属件必须挂在身上**。冲锋枪试过挂弹匣：弹匣在枪管下方、枪身在它上面收口到 `0.56H`，
中间空出一截，卡片里读成"浮着一块方块"。改成从枪管底垂下来的前握把，接缝天然连在一起。

**转身靠镜像，不靠旋转**：侧视的枪直接转 180° 会把握把朝上（画倒）。
所以瞄准方向朝左（`cos(aim) < 0`）时，先 `ctx.scale(1, -1)` 再画，握把始终朝下。

| 场合 | 画法 |
|---|---|
| 对局 | 枪画在本体**之前**，只露出枪身外段，球的轮廓保持完整 |
| 首页 | 枪画在本体**之后**，从球的 0.72r 处沿着固定角度伸出，读作"端着" |

首页端枪：`HOME_AIM = 2.50`（指向左下），`gsc = 1.9`。`HOME_AIM` 不跟鼠标变，只有白眼球跟。

无敌帧表现：**不做整体闪烁**（会造成视觉疲劳），而是把本体 alpha 降到 0.35，其余部分不变。

#### 5.3.2 脸（只有眼睛）

**黑眼在外，白眼球在内**：深色铺满整个眼形，正中嵌一颗白色眼球。
颜色还是那一对（浅 `rgba(238,252,255)`、深 `rgba(8,17,30)`）。
这一版是对调过一次之后改回来的：白底黑瞳看着干净，但白球一转到边上，
深色瞳仁就在白框里顶出一个完整的圆，读成"一颗珠子钉在中间"，不像在看人。
黑底白球反过来——白球顶到眼眶内壁时，黑只剩背侧一片弯月，才读得出视向。

**没有嘴。** 表情全部由眼形表达——一张只有眼睛的球，情绪反而更干净，
也不会因为嘴和枪、和球面透视打架。眼睛纵位 `-0.07r`，在球的视觉中心。

| 参数 | 取值 |
|---|---|
| 眼形 | 竖椭圆 `0.165r × 0.24r`（高宽比 1.45） |
| 眼间距 | 圆心各偏 `±0.31r` |
| 眼睛纵位 | `-0.07r` |
| 白眼球 | `0.44 × 0.52` 倍眼半径 |
| 白眼球行程 | 横 `1.00`、纵 `0.85`，乘 `(眼半径 − 白球半径)` |

白球 `0.44 × 0.52`，四周留的黑边足够厚，缩到 `r = 14` 也不会被压没。
行程取 `1.00`：白球走到底正好贴住眼眶内壁，**黑边不闭合成环**——
这是"黑眼白球"这套配色的关键，行程给小了（早期 0.62）白球永远悬在正中，黑圈永远是完整的。
纵向 `0.85` 不到 1，是因为眼眶纵径大、白球贴到上缘时会被椭圆收尖的形状切掉一块，
留 15% 余量刚好。

**三种状态**，差别全在眼形上：

| 状态 | 触发 | 眼 |
|---|---|---|
| 平静 `calm` | 默认 | 竖椭圆，不倾斜 |
| 不好受 `sad` | `hp/maxHp ≤ 0.35` | 纵向压到 90%，内眼角上挑 `0.17rad` |
| 瞪人 `angry` | `combat > 0` | 纵向压到 90%，**内上角被一条斜线切掉**，外上留尖角 |

优先级：`angry` > `sad` > `calm`。

**攻击态的那一刀**：以眼睛椭圆为裁切区，再与一个半平面求交——
直线从"外侧上方"（`-1.05rx, -1.15ry`）划到"内缘偏下"（`1.10rx, 0.15ry`），
切掉内上角，留下外上那个尖角，就是在瞪人。左右眼互为镜像（`inner = ±1`），
法线统一取朝下的一侧，免得镜像后切错半边。

**白球跟手**：视线方向乘 `min(1, 距离 / 60)`。60px 内按比例收，是为了鼠标贴着球时白球不抖；
超过 60px 就顶满——对局里瞄近处的敌人时，白球必须立刻转过去，慢半拍会显得人没在看你。
顶满时白球落在眼眶边缘，黑边成了弯月，所以**直视的完整黑圈只在鼠标压着球心时出现**，
其余时间都是偏心的。这也是把行程从 0.62 加到 1.00 的收益：整局下来脸一直在看，而不是一直在正襟危坐。

### 5.4 敌人

三类敌人共用同一张脸：**一对白眼球，一道斜着压下来的眉，一颗盯住正前方的瞳**。

| 参数 | 取值 | 说明 |
|---|---|---|
| 眼球 | `rx = max(2.3, 0.21r)`，`ry = 1.12rx` | 有下限，`r=10` 时也不至于缩成两个点 |
| 眼位 | `±0.33r`，纵 `-0.06r` | 与主角同一套比例，只是不会转 |
| 眉线 | 从外侧上方 `(-1.10rx, -1.15ry)` 划到内缘偏下 `(+1.10rx, +0.45ry)`，**保留线下** | 内侧压到眼下、外侧只擦过顶边：两条眉往中间聚，才叫怒 |
| 瞳 | 半径 `max(0.9, 0.30rx)`，位置 `(0, +0.30ry)`，`rgba(12,20,32,0.92)` | 压在眉下、稍偏下，是"低头瞪你" |
| 描边 | `rgba(8,14,24,0.72)`，线宽 `max(0.9, 0.24rx)` | 受击变白时靠它保住眼球形状 |

画法：整颗眼先铺深色（这是眼窝），再把路径裁进椭圆、裁掉眉线以上的部分，填白；
瞳最后画在白色里。所以深色的那一圈既是眼眶也是眉，不需要另画眉毛——
**眉坐在眼球里**，小尺寸下也不会多出一条糊线。

**为什么不画眉毛**：`r=10` 时眼睛只有 4.6px，眉若摆在眼球外面，两条线要么糊进眼眶、
要么离得太远读成"头上有两根毛"。放进去，眼形本身就带怒气。

**这是愤怒，不是呆滞**：早先版本瞳孔是一个 ×，读得出「这双眼睛不工作了」；
现在眉往下压、瞳盯住前方，读的是「它冲你来了」。两种都成立，别混着用。

炮手的三个专属图元：

| 元素 | 画法 |
|---|---|
| 蓄能环 | 半径 `r+7`，从 12 点顺时针，扫过角度 = `charge / 0.75`；线宽 2.5，`rgba(255,138,61, 0.50→0.95)` |
| 瞄准线 | 蓄能过 `0.55s` 才出现，从 `r+8` 拉到 620px，`rgba(255,138,61, 0.10→0.32)`，线宽 1 |
| 敌弹 | 菱形飞镖：前尖 `1.25r`、后尖 `0.9r`、半宽 `0.78r`，填充 `#ff8a3d`，描边 `rgba(46,14,4,0.85)`；拖尾 4px `rgba(255,138,61,0.42)` |

炮手的血条画在 `-r-14`（其余敌人 `-r-9`），给蓄能环让位。

**敌弹是菱形，玩家子弹是圆点**：靠形状区分敌我，不只靠颜色。

**士兵不画眼睛**：一条横过脸的护目镜（深色框 `0.40r` 高 + 内侧一条亮条）。其他敌人都是「眼睛球」，一眼分得开。
枪画在本体**之前**，从 `0.66r` 处伸出，只露枪管；AL-08 明显更长，那就是「打掉他」的目标提示。
士兵的子弹是**品红**菱形，和炮手的橙弹靠颜色分开。

**预告必须早于伤害**：环走满才发、线一出就定死——玩家永远有 0.95s 的可见窗口，
而且蓄能期间它几乎站定。这两条是远程敌人不烦人的全部前提。

其余：

- 血条仅在 `hp < maxHp` 时显示，位于 `(-r, -r-9)`，宽 2r，高 4px
- 血条底槽 `rgba(0,0,0,0.55)`，填充 `#ff5b5b`，**不描边**
- 受击 0.12s 内本体填充替换为 `#ffffff`，其余层不变（眼睛照画，所以白闪时脸还在）
- 大型敌人在血条外增加 1px 深色轮廓，提高在暗背景上的可辨识度

### 5.6 墙体（单人围城）

墙不是"描边矩形"，是**有厚度的实体**：深色板身 + 受光的上缘 + 背光的一条暗边。

```
① 板身   fillRect(x, y, w, h)            rgba(2,6,12,0.55)
② 暗边   fillRect(x, y+h-4, w, 4)        rgba(0,0,0,0.25)     ← 下缘，做厚度
③ 受光   水平墙(w≥h)：fillRect(x, y, w, 2)
         竖直墙(w<h)：fillRect(x, y, 2, h)                      ← 左缘，光源在左上
         颜色 rgba(140,235,255,0.25)
```

- 板身**比背景更暗**：画面是被照亮的场地，墙是挡光的东西。反过来（墙比地亮）会让墙读成 UI 面板
- 受光边只画一条，位置跟着长边走，这样细长的墙和方块墙都能读对方向
- 不做圆角、不做渐变、不做纹理

**门洞呼吸条**（只画开放中的入口）：

```
横门洞：fillRect(s.x-48, 16, 96, 12)
竖门洞：fillRect(16 或 W-28, s.y-48, 12, 96)
颜色：rgba(255,91,91, 0.12 + sin(t*2.4 + i)*0.08)
```

它借用威胁色是**允许且唯一**的例外：门洞就是把威胁送进来的地方。

## 6. HUD 组件库

所有组件以屏幕左上角为原点计算，`W`、`H` 为视口尺寸。下列数值**直接可用**。

### 6.1 资源条（血条 / 通用进度）

| 项    | 值                                                               |
| ---- | --------------------------------------------------------------- |
| 位置   | `(24, 24)`                                                      |
| 尺寸   | `244 × 14`                                                      |
| 底槽   | `rgba(255,255,255,0.09)`                                        |
| 填充   | 比例 > 0.35：`#2ee6a8 → #8ff7d0`；≤ 0.35：`#ff3b3b → #ff9b6b`（左→右线性） |
| 描边   | 1px `rgba(255,255,255,0.18)`，`strokeRect(x+0.5, y+0.5, w, h)`   |
| 说明文字 | `(24, 62)`，12px/500 mono，`text-align: left`，内容 `HP 100 / 100`   |
| 武器行 | `(24, 82)`，13px/600 mono，内容 `AL-18 · 三连发`；平时 `rgba(150,190,225,0.75)`，切模式后 0.7s 内换成主角色 |
| 按键提示 | `(24, 99)`，12px/500 mono，`M 切换`（只有一种模式的枪写 `固定模式`）；alpha 0.62，与武器行同时提亮 |

```js
function bar(x, y, w, h, ratio) {
  ctx.fillStyle = "rgba(255,255,255,0.09)";
  ctx.fillRect(x, y, w, h);
  var g = ctx.createLinearGradient(x, 0, x + w, 0);
  if (ratio > 0.35) { g.addColorStop(0, "#2ee6a8"); g.addColorStop(1, "#8ff7d0"); }
  else { g.addColorStop(0, "#ff3b3b"); g.addColorStop(1, "#ff9b6b"); }
  ctx.fillStyle = g;
  ctx.fillRect(x, y, w * Math.max(0, Math.min(1, ratio)), h);
  ctx.strokeStyle = "rgba(255,255,255,0.18)";
  ctx.lineWidth = 1;
  ctx.strokeRect(x + 0.5, y + 0.5, w, h);
}
```

| 标语 | `(49, 156)` | `方寸之内，退无可退。` 13px/500 字距 0.08em `rgba(160,205,240,0.85)` |
| 主角 | 屏幕正中偏上 `(W/2, H/2 - 28)` | 球半径 `clamp(min(W,H) × 0.068, 36, 58)`——1440×900 上约 58，1100×700 上约 48。光环 r+6、`rgba(124,231,255,0.18)` |

主角是**定姿**的：枪固定指向左下（`HOME_AIM = 2.50`，即 143°），画在本体之上、从球的 0.64r 处伸出，
`gsc = 1.9`；**不跟鼠标转**。会动的只有白眼球——它始终追着鼠标，是首页唯一的"活"信号。

为什么枪不跟鼠标：首页不是对局，鼠标在这里是"指针"而不是"准星"。让枪口追着指针转，
画面会一直抖，而且和下面两枚按钮抢注意力。定姿读起来才是"这个人站在这里，端着枪"。

**端着枪会累**，所以还要一点微摆——两个互质频率的正弦叠加，单频看起来像机械振动：

```
sway = sin(t·1.15)·0.68 + sin(t·0.53 + 1.2)·0.32      // -1..1
枪的角度 = HOME_AIM + sway·0.055                        // ±3.2°
身体纵位 += sin(t·1.15 + 0.6)·0.030r                    // ±1.7px（r=58 时）
```

幅度必须小：枪口偏 3° 在大球上就是 5px，再大就从"呼吸"变成"发抖"。

首页**不放操作提示**。提示全局只出现一次，在模式页底部（见 7.1.4）。

#### 7.1.5 交互

| 操作 | 结果 |
|---|---|
| 点「装备选择」/「模式选择」 | 进入对应子页，**不直接开局** |
| 滚轮 | 只在纵排且内容超出视口时生效；横向排法下滚轮不响应 |
| 点装备卡 | 切换装备，立即生效；回首页后按钮第三行跟着变 |
| 点模式卡 | 切换模式，不开始 |
| 点「开始游戏」 | 按当前装备与模式开局 |
| 点空白处 | 无反应（首页与模式页都不再有"任意点击开始"） |
| `Esc` | 子页 → `home`；对局 → 暂停 |
| `Space` / `Enter` | `home` → 模式页；`mode` → 开局；`equip` → 回 `home` |

**按下与抬起**（所有卡片与按钮统一）：

```
mousedown  记录 pressId，立刻换成按下态——反馈落在手指落下的那一帧，不等抬起
mouseup    指针仍压在同一块上才执行；中途滑走 = 反悔，什么都不发生
```

- 这是按钮而不是链接：按下有回应，抬起才生效，误按可以拖开取消

**动效**（界面里所有过渡都走这一套，对局中不跑）：

| 量 | 做法 | 时间 |
|---|---|---|
| 悬停量 `h` | 每个元素一个 0→1 的进度，`a += (目标 - a) × (1 - pow(1e-5, dt))` | 约 0.09s 到 63% |
| 按下量 `p` | 同上，目标来自 `pressId` | 同上 |
| 填充 / 描边 / 文字亮度 | 由 `h`、`p` 连续插值，没有"跳一档" | 跟 `h`、`p` |
| 按下缩放 | 绕自身中心 `scale(1 - 0.03p)`，文字跟着缩 | 跟 `p` |
| 箭头位移 | `x + 3h` | 跟 `h` |
| 准星半径 | `9 + 3 × 最大悬停量` | 跟 `h` |
| 换页 | 整页 `alpha` 0→1、缩放 0.982→1.0，**只做材料到位，不做位移** | 线性 0.14s |

`pow(1e-5, dt)` 是一阶临界阻尼：从当前值出发、不过冲、可随时被中断改向。
不用 `ease` 曲线，也不用 CSS 过渡——两者都无法在目标变化时从当前值平滑续上。
- 已选中的卡片按下去也要亮一档（青色填充 0.10 → 0.19）——"我已经选它了"不等于"按下去不用理我"
- 不许在 `mousedown` 里直接换页——那样按下态一瞬间就被新页面覆盖，玩家看不到任何反馈
- 已按下时把指针拖出去再拖回来，照样可以提交（不记"曾经离开过"）

- 不用琥珀色：琥珀在旧启动器里表示"作品状态"，这里的青色才是"你选中的东西"
- 卡片不做圆角以外的变形、不加阴影、不加图标
- 放置按钮的位置就是它的形状：不做隐藏菜单、不做滑入抽屉

### 7.2 暂停

| 元素 | 位置 | 规格 |
|---|---|---|
| 标题 | `(W/2, H/2 - 44)` | 44px/800 mono，`#eef8ff`，内容 `已暂停` |
| 提示 | `(W/2, H/2 - 6)` | 14px/500 mono，`rgba(160,205,240,0.8)`，内容 `按 Esc 继续` |
| 退出本局 | `(W/2 - 92, H/2 + 30)`，184×46 | 见下 |

暂停屏**只放一个按钮**，就是出口：

```
圆角 10，1px 描边
常态   填充 rgba(255,255,255,0.07)   描边 rgba(255,91,91,0.34)
悬停   填充 rgba(255,91,91,0.14)     描边 rgba(255,120,120,0.85)
按下   填充 rgba(255,91,91,0.22)     描边同上
文字   `退出本局` 15px/600 于 (w/2, 22)，`ABANDON RUN` 10px/500 字距 0.20em 于 (w/2, 38)
       常态 rgba(255,150,150,0.92)，悬停与按下转亮
```

用威胁色而不是主角色：这颗按钮丢掉的是一整局，不是"继续前进"。青色在这里会被读成推荐操作。

暂停时背景仍在渲染（粒子继续动，网格保持静止），只是 `update()` 不执行。这是"活着的暂停"。
按 Esc 继续，点「退出本局」回到首页——**对局中途没有任何键盘出口**，只能靠这颗按钮，所以它不能藏起来。

## 8. 动效

### 8.1 时长阶梯（只有这 8 档）

| 时长 | 用途 |
|---|---|
| 0.07s | 枪口火焰 |
| ≈0.09s | 界面悬停 / 按下的进度收敛（`pow(1e-5, dt)` 的时间常数，不是硬编码时长） |
| 0.14s | 换页淡入（线性） |
| 0.12s | 命中白闪 |
| 0.15s | 冲刺持续、弹药槽放大回落 |
| 0.45s | 滑铲、拾取反馈 |
| 0.60s | 受击红边衰减 |
| 1.60s | 横幅淡出 |

**禁止**：缓动函数（`ease-in-out`、`cubic-bezier`）。所有过渡均为线性或指数衰减 `Math.pow(k, dt)`。街机手感来自"快起快落"，曲线缓动会让它变软。

## 9. 可访问性

本项目追求克制的美术，已经天然规避了大部分问题，但以下四条必须遵守：

| 项 | 要求 |
|---|---|
| 对比度 | 文本与背景对比 ≥ 4.5:1。`#eaf6ff` 对 `#05070c` 为 16:1，安全；`rgba(180,205,230,0.7)` 对背景约 6:1，达标 |
| 不只靠颜色 | 敌人除颜色外必须有**尺寸差异**（10 / 15 / 26 三档），色盲用户靠大小区分 |
| 红绿不并置 | `#ff5b5b` 与 `#5df2a0` 不得紧邻出现（血条填充渐变已避开这一组合） |
| 闪烁频率 | 任何闪烁 ≤ 12Hz；全屏红闪为一次性衰减，不循环 |

## 10. 反例（出现即视为缺陷）

1. 用 `shadowBlur` 做辉光 —— 性能不可控，改用 r+6 半透明垫圆
2. 血条做成圆角/异形 —— 必须直角矩形
3. HUD 加投影或描边文字 —— 只用纯色填充
4. 分数用 body 字族 —— 变宽数字会导致版面抖动
5. 对局 HUD 里放按钮 —— 对局中没有任何按钮，交互只有鼠标与键盘
6. 初始界面放 Logo 图标、可变副标题 —— 文字只有：名字、固定标语、入口名、装备名与数值、模式名、操作提示。标语固定为 1.2 那一句，不得增删改
7. 结算屏加"再来一次"以外的任何按钮
8. 用 `ease` 缓动做淡入、做页面转场
9. 给背景加噪点、扫描线、CRT 滤镜
10. 在画面中心常驻显示波次数或倒计时
11. 按钮按下去没有任何视觉变化，或按下就直接执行、看不到按下态
12. 用 `mousedown` 提交界面操作——按下态会被新页面吃掉，等于没有反馈
13. 给只有眼睛的脸再加一张嘴——嘴会和枪、和球面透视打架，情绪靠眼形就够
14. 卡片/按钮不加受光边，整块读成贴在背景上的一块半透明色
