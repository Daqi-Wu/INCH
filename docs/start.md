# INCH · 方寸 —— 系列设计与实现规格

> 一屏之内，退无可退。

本文档用于在另一个工作区从零实现本系列游戏。所有数值均为**建议实现值**，不是参考值——照抄即可得到一致手感。凡本文档未提及的视觉细节，以第 3 节 Design Token 为准，不得自由发挥。

---

## 0. 给实现者

1. 每款游戏 = **一个 HTML 文件**，双击打开就能玩。不得引入构建步骤、不得引用外部 CDN、不得有网络请求、不得有加载画面。
2. 先读第 1–4 节（系列公理、技术形态、视觉语言、手感），这是八款共用的底座。
3. 再读第 5 节对应的那一款。第 5.1 节《围城》是**已完成的基准实现**，其余七款必须与它在视觉、操作、手感上可无缝并置。
4. 第 6 节是文件约定，第 7 节是验收清单——交付前逐条自查。

## 1. 系列定义

### 1.1 名字

| 项 | 值 |
|---|---|
| 中文系列名 | 方寸 |
| 英文系列名 | INCH |
| 落款格式 | `方寸 · 围城` / `INCH · SIEGE` |
| 分隔符 | 中文用间隔号「·」，英文用「·」前后各一个空格 |

系列名固定排在游戏名之前，字号小一号，字重 400；游戏名是主语，字重 500。不得使用破折号、斜杠、冒号。

### 1.2 标语

`一屏之内，退无可退。`

用于合集入口页与系列片头，字号 13px，颜色 `rgba(160,205,240,0.85)`，居中，位于系列名下方 28px。

### 1.3 命名三原则

1. **两个字**，不加形容词
2. **重心在名词**——"井""桥""巷"是可以站进去的空间，"勇""激""狂"不是
3. **名字里藏着失败方式**——围城 = 会被围死，哑火 = 会打不出子弹

> 这一条是硬约束。新增游戏若不满足第 3 条，说明它的核心循环还没想清楚。

### 1.4 设计公理

这六条决定了系列为什么是一个系列，任何一款都不得违反：

| # | 公理 | 含义 |
|---|---|---|
| A1 | **一屏之内** | 无卷轴式世界地图、无镜头推拉、无场景切换。全部发生在单屏内（《空巷》《深井》的滚动是运动，不是场景切换） |
| A2 | **一局 90 秒到 5 分钟** | 死亡即结算，结算即重开，重开不超过 1 次点击 |
| A3 | **不解释玩法** | 菜单只有一行操作提示，没有教学关、没有弹窗说明 |
| A4 | **失败方式写在名字里** | 见 1.3 |
| A5 | **同一双手** | 八款共用同一套键位（见 2.4），不学习第二套操作 |
| A6 | **零资源** | 无图片、无音频文件、无字体文件。所有图形由 Canvas 图元绘制 |

## 2. 技术形态（硬约束）

### 2.1 文件

- 单个 `.html`，内联 `<style>` 与 `<script>`
- 总大小建议 < 40KB
- 编码 UTF-8，`<meta charset="UTF-8">`
- 视口：`width=device-width, initial-scale=1.0`
- 只支持桌面浏览器（Chrome / Edge 最新版），**不做移动端适配、不做触屏**

### 2.2 画布

```js
DPR = Math.min(window.devicePixelRatio || 1, 2)
canvas.width  = Math.floor(W * DPR)
canvas.height = Math.floor(H * DPR)
canvas.style.width  = W + "px"
canvas.style.height = H + "px"
ctx.setTransform(DPR, 0, 0, DPR, 0, 0)
```

- `W = innerWidth`，`H = innerHeight`，每次 `resize` 重算并重新 `setTransform`
- `html, body { overflow: hidden; margin: 0; }`
- 游戏区域 = 整个视口，不存在"画布外"

### 2.3 主循环

```js
dt = Math.min((now - last) / 1000, 0.05)
```

- 单 `requestAnimationFrame` 循环，`dt` 上限 0.05s（切标签页回来不会瞬移）
- 所有运动以 `dt` 为单位（px/s、s/次），**不得写死每帧增量**
- 状态机：`"menu" | "playing" | "paused" | "over"`，单一枚举变量
- `paused` 与 `over` 状态下不执行 `update()`，但**继续执行 `render()`**

### 2.4 键位（八款统一，不得改动）

| 键 | 作用 | 备注 |
|---|---|---|
| `WASD` / 方向键 | 移动 | 对角线速度需归一化 |
| 鼠标移动 | 瞄准 / 定位 | 无瞄准概念的游戏忽略此项 |
| 鼠标左键 | 主操作（射击 / 部署 / 确认） | 按下即触发，不等待抬起 |
| `Shift` | 冲刺（统一命名：冲刺） | 冷却 1.25s，持续 0.15s，期间无敌 |
| `Esc` | 暂停 / 继续 | 切换 `playing` ⇄ `paused` |
| `R` | 重开 | 仅在 `over` 状态有效 |
| 任意点击 / `Space` / `Enter` | 开始 | 仅在 `menu` 状态有效 |

- 全局 `cursor: none`，鼠标指针由 Canvas 绘制（见 3.6）
- `window.addEventListener("blur", ...)` 时清空按键表与鼠标按下状态，防止卡键
- 禁用 `Space`、方向键的默认滚动行为

| 威胁 · 直接 | `#ff5b5b` | 追击型敌人、扣血、失败 |
| 威胁 · 快速 | `#ffd166` | 高速型敌人 |
| 威胁 · 重型 | `#a06bff` | 高血量敌人 |
| 收益 | `#5df2a0` | 回血道具、正向反馈 |

### 3.2 背景合成（八款共用，只改网格运动）

```
径向渐变：中心 (W/2, H/2)，内半径 60，外半径 max(W,H)*0.78
  0%   #101728
  55%  #0a0e18
  100% #05070c

网格：步长 64px，线宽 1px，颜色 rgba(90,130,190,0.075)
  坐标取整 + 0.5 防止模糊

暗角：径向渐变，内半径 min(W,H)*0.42，外半径 max(W,H)*0.85
  0%   rgba(0,0,0,0)
  100% rgba(0,0,0,0.55)
```

网格的**运动方式**是每款游戏的身份标识，必须按下表实现：

| 游戏 | 网格运动 | 表达 |
|---|---|---|
| 围城 | 双向慢漂移，水平 14px/s、垂直 9px/s | 静止的世界在呼吸 |
| 空巷 | 水平左移，速度 = 玩家当前速度 | 前进 |
| 深井 | 垂直下移，速度随深度递增 | 坠落 |
| 断桥 | 完全静止 | 阵地 |
| 哑火 | 完全静止，且网格透明度提到 0.11 | 密室 |
| 尾灯 | 垂直下移，速度 = 车速 | 行驶 |
| 逆流 | 水平左移，恒定 180px/s | 被冲走 |
| 引信 | 完全静止，且网格透明度降到 0.04 | 引信才是主角 |

### 3.3 字体

```css

font-family: ui-monospace, Consolas, monospace;                          /* HUD 与标题 */
```

| 用途 | 字号 | 字重 | 字族 |
|---|---|---|---|
| 游戏主标题 | 62px | 800 | mono |
| 关卡/波次横幅 | 52px | 800 | mono |
| 结算主数字 | 30px | 700 | mono |
| 分数 HUD | 26px | 700 | mono |
| 菜单提示行 | 15px | 500 | mono |
| 按钮/可交互文字 | 16px | 600 | mono |
| 副信息 | 12–13px | 500 | mono |

中文字距：`letter-spacing: 0.12em`（仅标题与大字使用）。

### 3.4 实体描边与光

- 所有实体（玩家、敌人、道具）均为**圆形**，使用径向渐变填充 + 2px 描边
- 径向渐变的高光点位于左上 `(-r*0.3, -r*0.35)`，模拟单一光源
- **不使用 `shadowBlur`**（性能不可控）。需要"发光"感时，用比本体大 6px 的半透明同色圆垫底，透明度 0.14–0.16
- 所有实体在地面有椭圆或圆形阴影：`rgba(0,0,0,0.4–0.45)`，向下偏移 4–5px

### 3.7 动效参数

| 效果 | 参数 |
|---|---|
| 屏震 | 幅度上限 16，衰减 26/s，实际位移 = `rand(-shake, shake) * 0.3`，作用于整个场景的 `translate` |
| 粒子 | 方形（`fillRect`），边长 1.5–3.6px，寿命 0.25–0.7s，速度阻尼 `pow(0.02, dt)`，透明度 = `life / maxLife` |
| 枪口火焰 | 存活 0.07s，半径 `8 + progress*60`，色 `rgba(255,235,150,0.85)` |
| 命中白闪 | 敌人填充改为 `#ffffff`，持续 0.12s |
| 受击红边 | 屏幕径向渐变，边缘 `rgba(255,0,0, 0.45 * flash)`，`flash` 从 0.6 线性降到 0 |
| 无敌闪烁 | `invuln > 0` 时按 `Math.floor(invuln*22)%2` 交替，透明的一帧 alpha = 0.35 |
| 横幅淡出 | `alpha = min(1, bannerTime / 0.4)` |
| 按钮呼吸 | `alpha = 0.55 + sin(t/320)*0.45` |

## 4. 手感规范

### 4.1 打击感四件套

任何一次"命中"必须同时触发以下四项，缺一不可：

1. **白闪**——被击中对象 0.12s 变白
2. **击退**——给目标施加 0.012 倍弹道速度的位移冲量，随时间指数衰减
3. **火花**——命中点爆出 5 个同色系粒子，初速 150 左右
4. **微震**——`shake += 1.6`，上限 9（击杀时 `+= 4`，上限 14）

### 4.2 输入宽容

- **开火**：按下即发射，不等待抬起；冷却按固定间隔（射击类 0.105s）
- **跳跃**（空巷 / 逆流）：落地前 0.08s 内按跳记入缓冲；离开平台后 0.1s 内仍可跳（coyote time）
- **冲刺**：无敌帧覆盖整个 0.15s 位移过程，且冲刺中不受伤、不减速
- **暂停与重开**：从任何状态都能在 1 帧内响应，不等待动画结束

### 4.3 难度曲线通则

- 所有数值成长走**线性 + 轻微指数**，不得阶跃
- 每波敌人血量 `×(1 + (wave-1) × 0.17)`，速度 `×(1 + (wave-1) × 0.02)`
- 每波敌人数量 `4 + floor(wave × 2.2)`
- 波间间隔 2.0s；首波延迟 0.9s
- 场上敌人上限 46（性能与可玩性共同决定）

### 4.4 死亡与重开

- 死亡瞬间：60 颗红色粒子 + 20 颗白色粒子，`shake = 22`，立即切 `over` 状态
- 不播放死亡动画，不做慢动作，不做黑屏过渡
- 结算屏出现到可重开之间**无延迟**

## 5. 八款游戏规格

### 5.1 方寸 · 围城 / INCH · SIEGE —— 波次射击【基准实现，已完成】

俯视角。玩家在单屏内移动射击，敌人从四边涌入，波次无限。

**核心循环**：移动走位 → 瞄准射击 → 清空一波 → 更强的下一波

**参数**

| 对象 | 参数 |
|---|---|
| 玩家 | r=14，速度 265px/s，HP 100 |
| 冲刺 | 900px/s 持续 0.15s，冷却 1.25s |
| 子弹 | 速度 1020px/s，r=3.6，寿命 0.85s，伤害 26，射速 0.105s/发，散布 ±0.035rad |
| 追击兵 chaser | r=15，HP 30，速度 100，接触伤害 12，分值 10，色 `#ff5b5b` |
| 快速兵 fast | r=10，HP 16，速度 190，接触伤害 8，分值 15，色 `#ffd166`（第 3 波起） |
| 重装兵 tank | r=26，HP 130，速度 58，接触伤害 22，分值 30，色 `#a06bff`（第 4 波起） |
| 出生点 | 屏幕外 60px 的四边随机点 |
| 接触伤害 | 触发后玩家无敌 0.55s，敌人攻击冷却 0.7s，双方互相击退 320 |
| 回血道具 | 击杀时 13% 概率掉落，回复 28 HP，存活 13s |

**敌人 AI**：直线追击 + 正弦横向摆动（振幅系数 0.28）+ 同伴分离力。分离力按重叠深度 `×(r1+r2-d)×2.2` 计算，防止叠成一坨。

**失败**：HP ≤ 0

**得分**：累加击杀分值

**该作独有 UI**：冲刺冷却环（玩家外圈 r+8，从 12 点方向顺时针填充）、敌人头顶血条（仅受伤后显示，宽度 = 2r，高 4px）

### 5.2 方寸 · 空巷 / INCH · ALLEY

横版无尽跑酷，身后有一堵持续逼近的黑墙。

**核心循环**：自动向右跑 → 跳过/滑过障碍 → 撞到就减速 → 被黑墙吞掉

**关键机制**：黑墙速度 = 玩家当前跑速 × **1.055**。也就是说，只要不出错，墙永远追不上；一旦撞障碍（速度降到 0.55 倍、持续 0.8s），墙立刻逼近。玩家从"领先很多"到"被吃掉"通常只有 2 次失误的距离——这是全部紧张感的来源。

**参数**

| 项 | 值 |
|---|---|
| 玩家 | 矩形 34×54，跑速 320px/s 起，每 100m +4px/s |
| 跳跃 | 初速 -640，重力 1900，允许 1 次二段跳（初速 -520） |
| 滑铲 | 持续 0.45s，碰撞高度 28，冷却 0.6s |
| 黑墙 | 初始位于玩家左侧 200px，速度 = 跑速 × 1.055，宽度 40px |
| 撞障碍惩罚 | 跑速 ×0.55 持续 0.8s，墙不减速 |
| 障碍类型 | 矮障（跳）、悬空管道（滑）、地缝（跳，宽 70–130） |
| 生成间隔 | 380–620px 随机 |
| 得分 | 1m = 1 分 |

**渲染要点**：玩家是矩形而非圆形（该系列唯一例外，因为有明确的"站/滑"两种姿态）；网格水平滚动，速度实时等于跑速；黑墙为纯黑到边缘的红噪点渐变，边缘 3px 抖动。

**失败**：黑墙左边缘越过玩家右边缘

**该作独有 UI**：顶部中央一条 320×6 的"墙距"横条，从白到红渐变，长度 = 玩家与墙的距离 / 200

### 5.3 方寸 · 深井 / INCH · SHAFT

垂直无限下坠，穿过逐渐收窄的井道。

**核心循环**：下坠 → 左右微调 → 穿过凸起 → 越深越窄越快

**参数**

| 项 | 值 |
|---|---|
| 重力 | 780px/s²，终端速度 1250px/s |
| 横向 | 最大速度 430px/s，加速度 3200px/s²（带 0.14s 惯性手感） |
| 井道宽度 | 420px → 240px 线性收窄（2000m 内完成） |
| 凸起生成 | 每 400px 深度一对，左右交替错位 |
| 撞壁 | 扣 20 HP，弹开 60px，无敌 0.5s，屏震 8 |
| 燃料罐 | 回复 15 HP，每 800px 深度生成 1 个 |
| 得分 | 深度 1px = 0.1 分 |

**渲染要点**：网格垂直流动且速度随下坠加速；井壁为暗色矩形 + 内侧 1px 冷光边（`rgba(124,231,255,0.35)`）；下落时对玩家施加轻微垂直拉伸（`scaleY 1.06`）表达速度。

**失败**：HP ≤ 0

**该作独有 UI**：屏幕右侧深度竖尺，宽 44px，每 100m 一条刻度线并标注数字，当前深度用青色短横指示

---

### 5.4 方寸 · 断桥 / INCH · BREACH

单线塔防。敌人只有一条路——桥面。

**核心循环**：赚零件 → 部署火力 → 清波 → 布更强的阵

**参数**

| 项 | 值 |
|---|---|
| 桥面 | 宽 = 屏宽 90%，高 60px，水平居中，垂直居中 |
| 部署格 | 10 个，等距分布于桥面 |
| 资源 | 初始 5 零件，每击杀 +1，每波结束 +2 |
| 枪塔 | 3 零件，20 DPS，射程 180px，射速 0.5s |
| 减速桩 | 2 零件，范围内敌人速度 -45%，持续 2s，射程 120px |
| 地雷 | 4 零件，一次性 80 伤害，触发半径 50px |
| 敌人 | 从左侧桥头进入，直线行进至右端，速度 60–110px/s |
| 波次 | 12 波，8 波后敌人开始有护甲（伤害 -30%） |
| 血条 | 桥头 5 格缺口，每漏 1 个敌人塌 1 格 |

**渲染要点**：网格完全静止；桥面比背景亮 8%（`rgba(255,255,255,0.06)` 叠加）；敌人走过时在桥面留下 1.2s 淡出的涟漪圆。

**失败**：5 格缺口全塌

**该作独有 UI**：底部中央工具栏，三个 56×56 方格（枪塔/减速桩/地雷），显示图标轮廓与价格；当前零件数显示在工具栏右侧

---

### 5.5 方寸 · 哑火 / INCH · MISFIRE

弹药管理射击。子弹不够，但子弹会回来。

**核心循环**：算角度 → 一枪串多个 → 捡弹壳 → 再算

**关键机制**：子弹撞墙反弹（每次速度 -8%，最多 6 次后落地成弹壳）。打穿敌人不消失（穿透 2 个）。所以一发的价值取决于角度，而不是手速。

**参数**

| 项 | 值 |
|---|---|
| 初始弹药 | 6 发 |
| 玩家 | r=14，速度 210px/s（比围城慢，强调思考） |
| 子弹 | 速度 760px/s，穿透 2，反弹上限 6 次 |
| 反弹 | 速度 ×0.92，反弹点闪白 0.1s |
| 弹壳回收 | 走过即拾取，+1 发，弹壳存活 20s |
| 敌人 | 10 个/关，HP 30，速度 110，接触伤害 15 |
| 判定失败 | 弹药为 0 且场上仍有敌人，持续 3s |
| 得分 | 剩余弹药 × 10 + 击杀数 × 5 |

**渲染要点**：网格透明度提到 0.11（空间更"实"）；墙面用 2px 亮线框标出（`rgba(140,235,255,0.25)`）；房间边界比屏幕内缩 40px。

**该作独有 UI**：左上用**弹药槽**替代血条——6 个 36×8 的短横，有弹为青色实心，无弹为空心描边

---

### 5.6 方寸 · 尾灯 / INCH · TAILLIGHT

夜间驾驶。你只能看见车灯照到的地方。

**核心循环**：加速 → 车灯锥内识别障碍 → 变道 → 躲避追兵

**参数**

| 项 | 值 |
|---|---|
| 视角 | 俯视，车固定在 (W/2, H*0.72) |
| 车道 | 3 条，每道宽 100px，路面总宽 300px 居中 |
| 车速 | 320px/s 起，每 10s +18 |
| 车灯锥 | 半角 26°，长度 520px，锥内正常亮度，锥外亮度 6% |
| 障碍 | 静止路障（矩形 40×40）、慢车（有红色尾灯点，需变道超越） |
| 碰撞 | 速度 ×0.5 持续 1s，扣 1 格车损，屏震 12 |
| 车损 | 3 格 |
| 得分 | 距离 1px = 0.05 分 |

**渲染要点**：该作是系列唯一以"黑暗"为主体的作品。锥外区域用 `rgba(0,0,0,0.94)` 覆盖（**不是**简单降低透明度）；屏幕最上方的红色尾灯点阵是玩家唯一的远距离信息来源，必须清晰可辨。

**失败**：3 格车损耗尽

**该作独有 UI**：右下速度表（三位数字 + 底下一段 120px 的弧形进度条）；左上 3 格车损用 3 个 24×14 的方块表示

---

### 5.7 方寸 · 逆流 / INCH · UPSTREAM

反向平台跳跃。世界向左流，你必须一直往右跳。

**核心循环**：跳上平台 → 不被推回左边 → 找下一个锚点

**参数**

| 项 | 值 |
|---|---|
| 卷轴 | 世界恒定向左 180px/s |
| 玩家 | 矩形 30×46，跑速 300px/s，跳跃 -580，重力 1750 |
| 平台 | 宽 90–180px，高 16px，间距 120–260px，从右向左进入 |
| 锚点 | 每 1200px 一个金色桩子，站上 2s 回满血，可用一次 |
| 水面 | 屏幕底部 80px，落入即死 |
| 得分 | 净前进距离，1px = 0.1 分 |

**渲染要点**：网格向左流动；水面为半透明冷蓝（`rgba(60,140,200,0.22)`）+ 顶部 2px 亮线；玩家被推近左边界时，左边界出现红色竖向警示光条。

**失败**：玩家左边缘越过 x=0，或落入水面

**该作独有 UI**：无血条。用一条屏幕底部之上的双向条替代——中点为零位，向右增长表示净前进，向左增长表示被推回，青色为进、红色为退

---

### 5.8 方寸 · 引信 / INCH · FUSE

倒计时反应。屏幕就是引信本身。

**核心循环**：扫视 → 认出最快的引信 → 按对键 → 熄灭

**参数**

| 项 | 值 |
|---|---|
| 初始引信数 | 5 条 |
| 单条倒计时 | 3.0–6.5s 随机 |
| 键位 | 每条绑定 `J K L` `;` `Space` 之一，键名显示在条上 |
| 按对 | 熄灭，+5 分，0.15s 内该条闪青色 |
| 按错 | 该条剩余时间 -1.5s，屏幕红闪 |
| 升级 | 每熄灭 5 条升一级：引信数 +1（上限 9），倒计时上限 -0.35s（下限 2.2s） |
| 得分 | 熄灭数 × 5 |

**渲染要点**：网格透明度降到 0.04（背景几乎退场）；引信为水平短条（宽 420px，高 26px），垂直均匀分布；末端有持续火星粒子（每帧 2 个，向上飘 0.4s）；剩余时间低于 25% 时条体转红并抖动。

**失败**：任意一条烧到 0

**该作独有 UI**：无 HUD。仅有屏幕顶部中央一行 12px 文字显示当前等级与熄灭总数

**定位**：这是系列里唯一的纯按键作品，用来调节节奏——其他七款都在"走位"，这一款在"视力"。

## 6. 文件与版本约定

### 6.1 目录

```
inch/
  index.html          合集入口（可选，列出八款卡片）
  inch-siege.html
  inch-alley.html
  inch-shaft.html
  inch-breach.html
  inch-misfire.html
  inch-taillight.html
  inch-upstream.html
  inch-fuse.html
```

- 文件名一律小写、连字符分隔、`inch-` 前缀
- 合集入口卡片：135×68 圆角 10，已完成的用琥珀色系（填充 `#633806`、描边 `#EF9F27`），未完成的用蓝色系（填充 `#0C447C`、描边 `#85B7EB`）

### 6.2 代码组织

单文件内部按以下顺序分段，用注释分隔（**不写行内注释以外的文档**）：

```
1. 常量与色板
2. 工具函数（rand / clamp / dist2 / lerp）
3. 画布与 DPR 适配
4. 输入绑定
5. 游戏状态对象
6. 初始化 / reset()
7. 更新 update(dt)
8. 绘制 draw*()
9. 主循环
```

- 不使用 ES Module、不使用 `class`（保持 IIFE + 函数，方便直接复制）
- 所有可调数值集中在第 1 段，散落在逻辑里的魔法数字视为缺陷

### 6.3 版本

- 每个文件顶部 HTML 注释标注：`<!-- INCH · SIEGE / v1.0 -->`
- 未完成的功能不写 TODO，直接不做
